# Design toolkit

The principles are in [AGENTS.md](../AGENTS.md#design). This is how to follow them with what the app already has.

## Character

WackCode is a dark, compact macOS workspace with a lime accent (`#c2ee4a` on `#111310` by default), a duck mascot (the app icon and the menu bar; `DuckMark` bobs as if afloat on the boot screen and ponders — head tilting, bubbles rising — beside reasoning rows in `PonderingDuck`), a robot for sub-agents (`RobotMark`), and a bead-trail working mark (`OrbitSpinner`: accent beads orbit like the send comet, then collapse with an outward ping when a tool lands). Ultra (Ultra Plan and the Ultra reasoning level) has its own mark, `UltraMark`: a 3×3 pixel wildcard whose lit pixel orbits like the beads, then spells `+`, `×` and a settled `✱`, beside labels that decode from glyph noise (`UltraLabel`), all in a fixed prism so it never reads as ordinary Plan or Max. New surfaces should feel like they belong to this cast rather than to a component library.

## Type

- Inter when installed, otherwise the system font. No web fonts: the CSP only allows `font-src 'self'`. Base size is 14px; rows sit around 13px and metadata at 10.5 to 12px.
- `"SFMono-Regular", Consolas, monospace` for code, file paths, branch names, and the names of tools, skills, commands and MCP servers.

## Colour

- **Adding a colour:** add a token to `TOKENS` in `src/theme.ts` (a recipe anchored on its default hex), add the same default under `:root` in `styles.css`, and use `var(--wc-…)`. `theme.test.ts` fails if the two disagree or a raw hex appears below `:root`.
- **Glows and tints:** `color-mix(in srgb, var(--wc-accent) N%, transparent)`, never an `rgb()` of the default accent.
- **Gradient accents:** the Solar, Lagoon, Verdant and Nebula presets paint accent-filled surfaces as a three-stop spectrum — buttons, badges, the composer send, the user's bubble. Fill with `--wc-accent-fill` (hover: `--wc-accent-fill-hover`), both of which fall back to the plain accent on every other preset. `--wc-accent` itself always stays one colour: text, borders, outlines and every `color-mix` need it solid, so a gradient never reaches them. The preset's `gradient` belongs to its accent — picking that accent anywhere keeps the spectrum — and the Theme dynamic palette blooms in its stops. Stop at three colours; Ultra's five-stop prism is identity, not a theme option.
- **Fixed meaning:** danger, warning, diff, success, the stop button and Ultra (`--wc-ultra*`: Ultra Plan and the Ultra reasoning level) keep their colours in every theme; Ultra's is a prism (cyan, violet, orchid, pink, peach stops, a lavender base, a near-white glow and `--wc-ultra-spectrum` for labels) that no single accent can match. The literals allowed below `:root` are listed in `SEMANTIC_COLOURS` in `theme.test.ts`.
- **Contrast is automatic:** a background too light for the app's fixed light text is darkened, and an accent too dark to read is lightened. Text on the accent uses `--wc-on-accent`.
- **Surfaces**, darkest to lightest: `--wc-well`, `--wc-sidebar`, `--wc-input`, `--wc-panel`, `--bg`, `--surface`, `--wc-composer`, `--wc-elevated`, `--surface-raised`, `--wc-menu`. Text: `--text`, `--wc-text-body`, `--text-soft`, `--text-dim`, `--text-faint`. Lines: `--border`, `--border-bright`.
- **See-through shell:** only `--wc-shell`, `--wc-header`, `--wc-sidebar`, `--wc-panel` and `--wc-composer-fade` turn translucent over an image or Liquid Glass (`shellVariables` in `theme.ts`). Content (bubbles, composer, cards, dialogs) never does — the one opt-in exception is the Classic Liquid Glass composer, a translucent pane over the app's own backdrop whose tint and background scrim keep the fixed light text legible.
- Code highlighting (`--wc-code-*`) and the terminal palette (`--wc-term-*`, bright variants from `terminal-theme.ts`) are derived from the accent, so check them in a few presets.

Test a new surface in at least the default, Mono and one colourful preset, with an image backdrop, and with Liquid Glass if you're on macOS 26.

## Shape

- Two radius tokens in `:root`: `--wc-radius-pill` for what you press and for chips, `--wc-radius-card` (14px) for content surfaces: tool sheets, work rows, code blocks. Reach for these before writing a new literal; older surfaces still carry their own.
- A content surface that opens has one anatomy: a lighter head band with a round accent mark, a dotted accent seam, then the body on `--wc-well`. Tool sheets, work rows and code fences all use it.
- A visual reply (`.visual-card`) sits directly on the conversation: a borderless, transparent frame at its content height, with Expand and Copy floating at the top-right on hover or keyboard focus. There is no title band or outer card. Over an image backdrop or Liquid Glass it gains a solid surface, card radius and 16 px padding so text stays readable. Its colours come from the app's theme tokens (`visualThemeVars`), so a chart is drawn in the user's accent and a light background renders a light visual.
- A canvas (`.canvas-*`) is the side panel's Canvas tab: a board filling the page edge to edge, which opens at most of the room beside the sidebar so it feels like a workspace, not a drawer. Its tools float over it in two solid pills (tools at the start, view at the end; the view pill stacks under the tools in a narrow panel) instead of a `.panel-header`. Its well is a plain surface, so the artboards' hairlines and drops carry the depth. Artboards sit on it at their real sizes with a hairline and a soft drop; their one-line name labels keep a constant screen size while the board scales (`--canvas-label-scale`), and each row's label, led by an accent dot, sits a fixed screen distance above them. Below a quarter zoom only the names stay (`.far`). Selection is an accent ring with the artboard's size, row and notes in a caption pill; playing adds a tinted halo and turns its Play pill into Stop. Present dims the whole window to the well and shows one artboard at a time over a floating bar. In the transcript a canvas is a compact card (accent mark, title, what the turn changed, a chevron) that rings while the agent draws. The board, pills and artboards are content, so they stay solid over an image backdrop or Liquid Glass.
- Inside a transcript every button is a pill or a circle (`.transcript-zone`); Settings keeps its squarer buttons.

## Motion

- **motion/react** (`motion`, `AnimatePresence`, `LayoutGroup`) for enter/exit, layout moves and anything tied to state: panel swaps, list reordering, the composer's hero→dock glide. Use springs for things that move. Read `useReducedMotion()` and drop transforms when it's true.
- **CSS** for hover feedback, ambient loops and choreography: transitions use `var(--ease)`; the shell's staggered `rebuild-in` entrance, the sidebar tiles' liquid outline, pulsing status dots, the send comet, the Ultra mark's arrival. The welcome comet follows the chosen composer style: one ring tracing its silhouette — a glass glint for Classic Liquid Glass, a wide capsule orbit, a crisper head for Terminal — and on Split Bar two rings half a turn apart, one on the card and one on the dock, so the pair reads as a single orbit crossing both surfaces. The Ultra mark's LED cycle is clocked in JS (`ultra-fx.ts`, one shared ticker) because its frames are discrete steps across nine cells, and the Ultra reasoning level's slider fill (`UltraGlyphField`) is a canvas glyph field that floods in and resolves; Max keeps its CSS sheen and streaming dots, so the two never look alike. Live compaction also draws on canvas: `CompactingStage`'s gravity well pulls file glyphs (documents, code pages, images) into an accent core that grows as it eats, escalating in acts the longer it runs — with a rare duck cameo — then collapses into the saved "Context compacted" row.
- **The Chat area** is a messenger stage, not a transcript: the hero's duck floats on a pond of light with drifting thought bubbles (they scatter while you type, the duck dives on send as the pill glides from centre to dock), the typing indicator is three bouncing dots with the duck beside it, replies wear a `PonderingDuck` avatar while live, and the jump-to-latest pill wiggles its duck when something new landed. `GLIDE_EASE` is shared by the composer glide and the first bubble's spring-up.
- **Quack Survivors** (the Games panel) draws on canvas from the same cast: the `DuckMark` duck, `OrbitSpinner`'s beads as the Orbit weapon, the send comet as Comet, the tool-landed ping as Ping, Flock's ducklings as the duck itself, tokens as XP. Bugs are the one place danger red appears for something other than an error (it marks what hurts) — splitter, mosquito and elite glyphs included; elites ring themselves in the accent, which marks what's special to kill, not what's dangerous. Under reduced motion the game still plays, without shake, bursts or bobbing.
- **Doodle Duck** (the Arcade's second game) climbs the same cast upward: the `DuckMark` duck again, the same danger-red bugs to stomp, and the accent reserved for what helps — springs, the bubble lift, the starlit ledges. The world itself carries the progression: lily pads on a pond give way to cloud ledges and then glowing pads among stars, each crossing announced once. The Arcade home's cards carry the same marks in miniature — danger-red bug dots under the survivors' duck, accent pads under the climber's. Under reduced motion the game still plays, without bobbing, twinkle, crumble jitter or bursts.
- **Direction means something:** a side-panel page slides in from the side its tab sits on (falling back to `swapDirection` in `side-panel.ts`); sub-agent tabs slide only the transcript. Switching between Code and Chat moves everything the same way (`areaDirection`): the switch's pill glides across, the sidebar's list slides, and the hero title leaves and arrives sideways, while a send still lifts it away. The duck joins every switch too (`AreaHop`): the window dims for a beat, it hops across the spotlit stage in the travel direction — two arcs and a wobble, or about one time in ten a full somersault, kin to the compaction stage's rare cameo — and the lights come back up on the arriving area as it hops off; under reduced motion it stays home.
- **Names get a beat:** when the auto-title model names a chat, the header's title swipes to the new name with an accent glint passing through the letters, and its sidebar row crossfades at the same moment (`TextSwap`, driven by `titlePulses`).
- **Dynamic backgrounds:** Glyph Flow is a decorative character field with empty-space click ripples; Colour Drift is a wash of prepainted blooms. Both follow only the selected chat, with quieter ink behind conversations and Settings. Theme palettes follow the accent (including Mono); Aurora and Sunset use dedicated decorative tokens, never semantic colours. Intensity controls ink strength, not speed. Reduce Motion shows a still composition; native loss of focus and document hiding cancel the frame loop.
- **Cheap properties:** animate `transform` and `opacity`. The image backdrop crossfades two pre-blurred layers rather than animating the blur.
- **Reduced motion:** a global rule collapses every duration to `.01ms`. A looping animation therefore also needs its own `@media (prefers-reduced-motion: reduce)` override beside it, setting a still end state so it doesn't flicker. The welcome comet is the one deliberate ambient exception.
- **Don't fight another animation.** Where Framer owns an element's transform (the composer), a CSS animation moves a wrapper instead.

## Components

- **Primitives** (`src/components/ui/`): `ConfirmDialog` (use `danger` for destructive actions), `Menu` / `MenuButton`, `Popover`, `Select`, `Tooltip`, `Checkbox` (a native checkbox, tri-state, with a drawn tick), `ImageLightbox`, and `useConfirmAction` (the two-click "Archive?"/"Delete?" arm on sidebar and Archived rows).
- **Buttons** (`styles.css`): `.primary-button`, `.secondary-button`, `.danger-button` (add `.compact` for dense rows), `.icon-button`, `.ghost-button`, `.text-button`, `.panel-button` in the chat header.
- **Icons** (`Icons.tsx`): one hand-drawn set on a 24px grid, 1.8 stroke, round caps, `currentColor`. Add a path and a name to `IconName`; don't pull in an icon library.
- **Settings pages** take the finished shape: a centred `.settings-page` column that opens with `SettingsHero` (an illustrated stage whose loop shows the page's state, a status pill, the page's main switch or action) and continues in solid `.settings-block` cards. Every page uses the shared parts except Computer use and Prompts (the same shape in their own classes) and Appearance (a centred column of its own). A page's detail views (a skill, a connection, an editor) open in the same column under a back link or the hero; an editor that saves explicitly shows its save bar only while it has changes (Settings › Providers). An empty state explains the feature and offers the ways in, rather than one grey line.
- **The Code composer** is an 18px card whose controls are all round: 28px circles and pills at one resting weight, so state carries the emphasis (a lit reasoning level, the mode pill sliding in its recessed track, a send button that is grey until there is something to send). Focus is a soft accent halo shared with Chat's composer. Its `/` and `@` pickers are menus in the tool sheets' language: a round mark per row, the name in mono, an accent wash on the active row, and a strip of key hints that stays put. Settings › Appearance offers five silhouettes (`appearance.composerStyle`, Code only): WackCode Classic, Classic Liquid Glass (the same card in a translucent pane, macOS 26+), Capsule (Attach and Send in a 26px pill's writing row, the metadata in a quiet strip beneath), Split Bar (input card above a floating dock), and Terminal (`❯` beside a monospace field over a status strip). Every style keeps the same controls, roles and focus halo; only the surface and where they sit change. The two Classic looks carry the run's status above the card as floating pills — the live "Working for" clock naming the tool in flight, and the todo list compressed to a pill whose popover holds the full tree; the transcript's own live clock yields to the timer pill there.
- **The plan card** is the transcript's one hero card: a head lit from its corner with a large mark, the plan's numbered steps drawn as round marks, the decision in a footer band. While a decision is owed it wears a halo, a breathing ring and an "Awaiting you" pill; an earlier proposal keeps the shape and drops the light. Ultra Plan's result takes the prism and the Ultra mark through the card's `--card-*` variables, and the skill review card is the same family.
- **A question and its record match.** The live card above the composer (`.question-option`) and the Asked sheet in the transcript (`.tool-option`) share one option shape, marker and picked state; change them together.
- **Popovers** take the card radius, rows with 9px corners, and the pickers' accent wash on what is in use. Tooltips are pills.
- **The sidebar** is shell, so its fills are tints. A project is a row led by a round monogram mark: grey with no open chats, accent-lit once it has some, filled solid for the project you are in. Its chats hang beneath on the dotted rail as single-line pills (state dot or bead trail, name, mode mark, age; archive takes the age's place on hover — delete lives only in the Archived view). New chat is the one accent-tinted call to action; the footer's round tiles keep their liquid outline.
- **The Code header** carries the chat's title over two small pills (folder, branch), split Build and Run pills, and the side panel's views as one pill track whose fill glides to the panel's front tab and rests nowhere when the panel is hidden. Beside a wide panel it tightens instead of breaking: Build and Run drop to their icons, and in a narrow column the folder pill and the track give way to the branch and one panel button. Its height (`--shell-head-h`) is the panel strip's, so one line runs across the window. The shared `.segmented` control and the new-chat project bar are the same pill shapes; a project's monogram is round wherever it appears.
- **The side panel** is a tabbed peer of the chat column. Its strip holds the tabs as pills on the shell (tints, never solid, so it stays see-through over an image or Liquid Glass) whose accent fill glides to the front tab, a ✕ revealed on hover and focus, "+" for views not open yet, then round Expand and Hide. A tab's icon sends out a ring (`.live`) while the agent is at work in that view, even from the back. Under the strip each view has a slim toolbar (`.panel-header`): what it is showing (the page, the branch and its totals, the shell), a status pill only when there is something to say, then round actions. An empty view is a mark inside a dotted orbit (`.panel-empty-mark`). Icon buttons in the panel are circles and its buttons are pills; the panel opens wide (half the room beside the sidebar) until it is dragged; the resizer shows a grab pill, not a lit edge, and a double-click goes back to that balance.
- **The sidebar** collapses whole: it slides out at its full width (⌃⌘S), and steps aside on its own when a wide panel needs the room, its toggle wearing an accent dot until it returns. The toggle glides between the sidebar's title strip and the traffic lights.
- **The browser** keeps its controls in two quiet rows under the panel head, without bands: round navigation in a recessed track, a pill address field with the composer's focus halo (a sheen crosses it while a page loads), and a Take control pill that wears the accent while you hold the page; then the viewport as a pill track of drawn devices with a gliding fill, its size and scale in mono, and the capture tools. Too narrow for its words, Take control keeps a drawn icon and its accessible name. The page rests on the plain well inside a frame drawn behind the native view: a grey ring at rest, the accent while you hold the page, a ring sent out while the agent uses it. Notices sit on the well above the page, never over it.
- **Changes** reads as a list over a sheet. Files are pills led by a round status mark (its colours are fixed), grouped under a name, a count and a dotted trail like the sidebar's dates; the open file wears the accent. The diff is a sheet: a head band naming the file, the dotted seam, the diff on the well. A comment is a card led by a round mark, in the warning's colours once its line has moved. The dock's tabs share one pill track with a gliding fill, and its sheet rises above the bar across a dotted seam. No left accent bars.
- **The tab bar** (optional) is a row of pills on the shell, so its fills are tints, never a solid surface. The active fill is one shared element that glides between tabs; each tab's state is a round badge (bead trail while working, a drawn glyph on a dot of the state's colour otherwise).
- **The agent asking the user** (questions, extension dialogs, the computer-use access card) renders inline above the composer (`InlineDialog`), not as a modal. Live status (goal loop, computer use) goes in a banner above the composer.

## Interaction and accessibility

- Icon-only buttons have an `aria-label`; square tiles put their label in a `Tooltip`.
- Actions revealed on hover (message actions, file rows) also appear on keyboard focus. Focus rings come from the global `:focus-visible` rule.
- Escape closes dialogs, popovers and menus.
- Show keyboard shortcuts with macOS glyphs (⌘⇧⌥⌃) in `<kbd>`.
- Components are tested with Testing Library role-based queries, so real roles and labels matter.

## Copy

- Short, plain sentences in the second person. Errors say what happened and what to do; Rust errors are shown to users verbatim, so write them as sentences.
- Name settings as `Settings › Section`.
- The agent is `agentName(...)` / `AssistantNameContext` (`src/agentName.ts`), never "Pi". Only genuine Pi product references (the package catalogue, subscription sign-in, the worker process) say Pi.
- Only changes that matter to a visitor update `README.md`; see the README rule in `AGENTS.md`.
